# v0.12.0

Gateway support for the Muqun 3.0 OpenCode workbench, with the existing terminal API retained for Muqun App 2.0.

## Changes and fixes

- Add an OpenCode 2 adapter and session API for messages, streaming output, child sessions, model and agent catalogs, permissions, inbox delivery, compaction, revert, skills, and worktrees.
- Repair session rename and other actions against the OpenCode 2.0.15 API contract. Rename and permission updates accept empty successful responses, and failed mutations are not retried against obsolete endpoints.
- Report OpenCode installation and connection readiness, including configured agent models. Require the current `/api/info` endpoint when discovering an OpenCode server.
- Read terminal slash commands from a locally cached command catalog. `muqun-gateway commands update` refreshes that catalog; the installer attempts the refresh automatically.
- Add optional multi-key and editor actions without changing the physical-key list consumed by older Apps.
- Preserve opaque agent identities in session snapshots and stabilize agent status notifications.
- Serve uploaded image content through authenticated URLs, with filename validation and retention limits.

## Compatibility

- **Muqun App 2.0:** the existing pairing, terminal, workspace, file, and agent-control routes remain available. API major remains 1 (API 1.8.0; content schema 1.5.0). New OpenCode workbench features require a newer App.
- Legacy terminal response envelopes remain in place. New shortcut sequences and text actions are returned in the separate `keyActions` field, so older Apps continue to consume single physical keys from `keys`.
- Herdr terminal integration requires Herdr 0.7.5 or newer. Agent collaboration requires a connected Herdr 0.9.0+ backend for the selected session; tmux retains ordinary terminal support.
- OpenCode workbench actions target the OpenCode 2.0.15 API contract and require an OpenCode 2 server exposing `/api/info`. Older OpenCode server APIs are not supported. This requirement does not prevent ordinary Herdr or tmux terminal use.

## Upgrade

Re-run the installer:

```sh
curl -fsSL https://muqun.dev/gateway.sh | sh
```

The installer replaces the binary and restarts the managed service while preserving saved pairings, device tokens, and backend settings. Restart manually if you run the Gateway outside its managed service. No configuration migration or re-pairing is required.

If command suggestions are empty after an offline upgrade, run `muqun-gateway commands update` when the host can reach the command catalog. Upgrade OpenCode separately before using the new workbench endpoints.
