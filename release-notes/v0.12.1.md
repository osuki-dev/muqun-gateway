# v0.12.1

A fix for updates that stopped with "stop the running gateway before importing its pairing identity".

## Changes and fixes

- **Updating no longer stops at the Herdr plugin import.** On a machine that still had files from an earlier Herdr plugin install, and whose standalone gateway runs on the same port, the installer mistook the standalone gateway for the plugin gateway and exited after it had already replaced the binary. Setup and the service reload never ran. The installer now leaves both pairings alone and continues when the standalone gateway:
  - has devices paired to its own identity,
  - has a device file that cannot be read, or
  - is currently running.

  It prints a notice with the device count on each side and the two ways forward. Your paired devices keep working, and nothing is imported behind your back.
- **`muqun-gateway import-herdr-plugin` names the gateway that is in the way.** When the standalone gateway holds the state directory, the error says so and gives its pid. For a gateway that runs as a service, it says how to stop it: `service uninstall`, then `stop`, then `service install` again after importing. Before, it pointed at "the running gateway" whichever one that was.

If you see the notice and the plugin pairing is left over from before you switched to the standalone gateway, move the directory it names aside. The notice then goes away. If your phones are paired to the plugin gateway instead, follow the import steps in the notice.

## Compatibility

- **Muqun App:** unchanged from v0.12.0. API 1.8.0 and content schema 1.5.0; no route, field or capability was added, removed or renamed.
- **Herdr:** terminal integration requires Herdr 0.7.5 or newer. Agent collaboration requires a connected Herdr 0.9.0+ backend.
- **OpenCode:** the workbench targets OpenCode 2.0.15 and requires an OpenCode 2 server exposing `/api/info`, as in v0.12.0.
- **Platforms:** macOS (arm64, x86_64) and Linux (x86_64, aarch64, musl).

## Upgrade

Re-run the installer:

```sh
curl -fsSL https://muqun.dev/gateway.sh | sh
```

Pairings, device tokens and backend settings are preserved. No configuration migration or re-pairing is required. If a previous update stopped at the import error, this run completes it.

## Known issue

On macOS, reloading the managed service during an update can occasionally fail with `launchctl bootstrap failed: 5: Input/output error`. The old gateway has not finished exiting when the new one is registered, and the gateway is left stopped. If `muqun-gateway service status` reports that the unit file exists but is not loaded, run `muqun-gateway service install` once more. A fix is planned for a following release.

## Validation

- `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test --locked` pass on macOS arm64 (680 passed, 0 failed).
- On the Mac that reported the failure:
  - the import step skipped with the notice and exit 0, with the standalone state directory unchanged
  - the remaining install steps completed
  - the launchd service came back on the new binary with all 7 paired devices and the OpenCode 2.0.15 engine connected
- The full `curl | sh` path runs against the published binary, so it is exercised only once this release is out.
