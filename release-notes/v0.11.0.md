# v0.11.0

A pane knows where it is, a read-only git diff for the file an agent is
touching, and a capability that is only announced where it can be honoured.

**This release is backward compatible with every App already in the field.**
The API surface gained routes, capabilities and one field; nothing was removed
or renamed. Apps decode gateway responses structurally and ignore keys they do
not know, so an older App talking to this gateway behaves exactly as it did
before. Upgrade the gateway on its own schedule.

## Changes and fixes

- Pane context and git, three routes in the content envelope behind two new
  capabilities, `pane_context` and `git_diff`. `context` answers where a pane
  is and what runs in it: the fenced cwd, the checkout it belongs to with its
  branch line and changed-file count, and the agent with its declared
  profile. `git/status` lists the working tree against HEAD with per-file
  totals; `git/diff` serves one file's unified patch a page at a time, cut on
  hunk boundaries so every page parses alone.
- git runs read-only and fenced: a fixed argument list, one validated path
  after a literal `--`, a five-second timeout, an 8 MiB stdout cap,
  `--no-optional-locks` so the agent working in the checkout never loses its
  index lock, and untracked symlinks refused rather than read through. git's
  stderr goes to the gateway log, never to a client.
- A page inside one long hunk is cut raw (with line counters carried across
  the cut) instead of being pulled back to a hunk boundary that left a phone
  four header lines and a "more" button. A rename is diffed with both paths:
  `old_path` rides after the new one and is validated the same way.
- `agent_collaboration` is announced only where it can be delivered: a
  connected Herdr 0.9.0+ backend. Every gateway used to announce it, tmux-only
  ones included, which cannot bind an assignment to an agent instance at all.
  `/health` now carries `backends[].capabilities` (always present, empty
  included), and the same key on the primary backend object; the gateway-wide
  `capabilities` array keeps `agent_collaboration` only when some configured
  session qualifies. tmux sessions keep every terminal capability and lose
  exactly the one claim they could never honour.
- Content schema 1.5.0, API 1.8.0.

## App compatibility

New capabilities: `pane_context`, `git_diff`. New field: `backends[].capabilities`.
No capability was removed. Apps detect features by capability, not by version.

- **An older App with this gateway** keeps working unchanged. It ignores the
  new routes and field. The one visible difference: on a tmux-only gateway it
  no longer sees `agent_collaboration`, which it could never use there, and
  shows its upgrade explanation instead of an assignment that goes nowhere.
- **A newer App with an older gateway** keeps working: without
  `backends[].capabilities` it falls back to the gateway-wide array, and the
  git panel stays hidden where `git_diff` is not announced.
- Agent collaboration still requires a connected Herdr 0.9.0+ backend for the
  selected session; the gateway now enforces what the notes for v0.10.0 only
  stated.

## Upgrade

No configuration or migration steps. Re-run the installer (`install.sh`): it
replaces the binary and restarts the managed service on macOS and Linux, so
the new routes and the `/health` shape are served straight away. A gateway
started by hand only needs starting again. Pairings, device tokens and
backend settings are untouched.

## Validation

`cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings` and
`cargo test --locked` pass on the release commit on macOS: 524 tests passed,
0 failed, 19 ignored. The test build had stopped compiling on macOS after the
last commit on `main` (libc declares `openpty`'s winsize pointer `*mut` there
and `*const` on Linux); the release commit carries the portable form.

Backward compatibility above was checked against the App's own client code:
the gateway client performs no schema validation on responses, the App reads
`backends[].capabilities` and falls back to the gateway-wide array when it is
absent, and the diff for this release removes no route, field or capability.

**Not verified, and worth knowing before you rely on it:**

- The git routes were exercised against a real checkout on macOS (the hunk
  cut and rename fixes came out of that run). No Linux checkout was used.
- The per-session `agent_collaboration` announcement was checked against the
  App's client code and unit tests, not a live paired assignment on a
  tmux-only gateway.
