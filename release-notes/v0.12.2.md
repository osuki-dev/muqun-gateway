# v0.12.2

Fixes updates on macOS that left the gateway stopped with `launchctl bootstrap failed: 5: Input/output error`. This was the known issue in v0.12.1.

## Changes and fixes

- **Reloading the macOS service no longer leaves the gateway stopped.** `muqun-gateway service install`, which the installer runs on every update, took the old agent down and registered the new one immediately. launchd can take a moment to release the old job, and a registration inside that window failed with error 5 and left nothing running. The reload now:
  - waits until launchd has released the old job and the old process has exited
  - then registers the new one, retrying for a few seconds while launchd catches up

  Any other launchd error is reported at once, with launchd's own message.
- **The installer checks that the gateway actually started.** An update or install used to print "running" whether or not the gateway came up. It now waits up to 20 seconds for it to answer.
  - If the gateway reports that it is not running, the installer fails and says where the log is and how to start it.
  - If the host cannot tell (for example, a minimal Linux without `ss`), it prints a warning instead of failing the install.

## Compatibility

- **Muqun App:** unchanged from v0.12.0. API 1.8.0 and content schema 1.5.0; no route, field or capability was added, removed or renamed.
- **Herdr:** terminal integration requires Herdr 0.7.5 or newer. Agent collaboration requires a connected Herdr 0.9.0+ backend.
- **OpenCode:** the workbench targets OpenCode 2.0.15 and requires an OpenCode 2 server exposing `/api/info`.
- **Platforms:** macOS (arm64, x86_64) and Linux (x86_64, aarch64, musl). Linux service handling is unchanged.

## Upgrade

Re-run the installer:

```sh
curl -fsSL https://muqun.dev/gateway.sh | sh
```

Pairings, device tokens and backend settings are preserved. No configuration migration or re-pairing is required.

The installer replaces the binary before it reloads the service, so the reload in this update already uses the fix. If an earlier update left the gateway stopped, `muqun-gateway service status` reports that the unit file exists but is not loaded. This update repairs that, or you can run `muqun-gateway service install` yourself.

## Validation

- `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test --locked` pass on macOS arm64 (683 passed, 0 failed), including new installer tests for a gateway that never starts and for a status check that cannot answer.
- The failure was reproduced deterministically on a real Mac by delaying launchd's release of the old job by 3 seconds:
  - v0.12.1 failed with exit status 5 and left the gateway stopped.
  - This release reloaded successfully every time.
- Full local runs of the installer against the real launchd service, with and without that delay, ended "updated and running" with all paired devices kept and the OpenCode engine connected.
