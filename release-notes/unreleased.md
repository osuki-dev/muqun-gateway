# Gateway preview

## Installation and updates

Gateway now resolves the stable and preview channels on muqun.dev. Each version has a manifest for all four Linux and macOS binaries. The installer and self-updater verify the download against its SHA-256 before running it and display the verified digest. Use `muqun-gateway update --channel preview --check` to check for a preview, and omit `--check` to install it. Installation retains the existing protection against downgrades.

On a fresh computer with Muqun Desktop, Gateway can pair before Desktop opens and discover the bundled terminal when it starts. Existing tmux and Herdr configurations are preserved.

## Agents, messages and history

- **Unified tool normalization, media/file cards, and workspace read hydration across all 11 agents**:
  - Canonicalized provider-specific tool names (`read_file` → `read`, `edit_file` → `edit`, `write_file` → `write`, `run_command` → `bash`, search tools), PascalCase inputs (`Path` → `path`, `CommandLine` → `command`), unified `metadata.files` diffs, shell `metadata.exit` status, and bare empty `{}`/`[]` outputs across ACP (Antigravity, Claude, Cursor, Copilot, Qoder, Fx), Pi, Codex, OpenCode, DeepSeek, and T3.
  - Unified image/file tool media normalization with explicit image-view byte sniffing (`AccountImageView`), rich document cards (PDF/Office/media), and bounded workspace-fenced line-numbered text excerpt hydration (`StartLine`/`EndLine`/`offset`/`limit`, capped at 200 lines / 16 KiB) for completed `read` calls whose adapters omit file bodies, while keeping source-code reads compact and never showing raw `/api/.../original` URLs as filenames.
- **Memory & runtime footprint reduction (`malloc_arena`, Tokio workers, SQLite cache, and remote wire size)**:
  - Bounded Linux glibc allocator arenas (`MALLOC_ARENA_MAX=2`), Tokio worker/blocking thread pools (`2–4` workers), and SQLite `cache_size` / `mmap_size`, with periodic `malloc_trim(0)` and `PRAGMA shrink_memory` maintenance cutting idle Gateway RSS by ~65% (~463 MiB → ~162 MiB).
  - Deduplicated redundant pure-text `ToolCall.content` copies on wire responses, routed >128 KiB WebSocket snapshot/window replies to gzip-compressed sealed HTTP via 413 fallback, parallelized cross-agent descendant lookups, skipped OpenCode queries for non-`ses_` parent IDs, and reused `context_usage` from OpenCode timeline fetches.
- **Unified account limits caching, Antigravity MCP compatibility, and cross-agent `@computer` support**:
  - Added single-flight 30 s manager-level `account_limits` caching with `?refresh=1` force refresh (shared by orchestration candidate selection).
  - Exposed underscore MCP tool names (`exec_run`, `fleet_list`, …) for Antigravity while accepting both dotted and underscore names on `tools/call`, and enabled `adds_mcp_servers` / `mcp_server_connected` across ACP and Pi drivers so `@computer` mentions (`computerTools` / `computer_ids`) work reliably across all agents.
- **OpenCode & Tailscale latency optimization and MCP Hub live tool testing**:
  - **OpenCode cold-open & session-load speedups**: Eliminated redundant message cloning in `OpencodeClient::message_list`, bypassed ambient HTTP proxies (`no_proxy`) on loopback OpenCode connections, parallelized `settled_list` catalog fetches, and cached session directories for `get_vcs_diff` so opening OpenCode sessions locally and over Tailscale is dramatically faster.
  - **MCP Hub tool schema inspection & live call endpoint**: `GET /api/mcp/upstreams` tool previews now include full `input_schema` definitions, and `POST /api/mcp/upstreams/{id}/call` allows authorized Desktop clients to invoke and test upstream MCP tools directly with bounded responses and secret redaction.
- **Unified MCP Hub (`mcp_hub_v1`), SEP-2640 Skills over MCP, SEP-2663 MCP Tasks, and Barrier Wakeup**:
  - **Unified MCP Hub (`mcp_hub_v1`)**: Configure external Streamable HTTP (including `https://` and local/Tailscale/LAN `http://`) and stdio MCP servers once in Gateway (`mcp.upstreams` or `GET/PUT/DELETE /api/mcp/upstreams*` and `POST /api/mcp/upstreams/{id}/probe`). `GET /api/mcp/upstreams` also exposes Muqun's own built-in `/mcp` server status, endpoint URL, auto-injection state, active assistant token count, built-in tools, and available skills. Every connected agent discovers upstream tools on demand via `hub.search_tools` (compact summary or full `inputSchema`) and invokes them via `hub.call_tool` with per-upstream access scopes (`local_only` default failing closed for delegated/remote peer tasks, `tasks`, `all`), tool-level `allowed_tools` / `denied_tools` wildcard ACLs (deny always wins), `shared` or `per_session` isolation, bounded timeouts, secret redaction on tool/skill outputs, and secret masking/preservation bound to unchanged HTTP origin or stdio command.
  - **MCP Hub & PTY security hardening**: Disables automatic HTTP redirects on upstream calls, enforces 4 MiB body/SSE/stdio line limits, blocks cloud metadata IPs (`169.254.169.254`, `169.254.170.2`, `fd00:ec2::254`, `metadata.google.internal`), embedded URL credentials, self-loop `/mcp` URLs, and smuggling/reserved headers; guards user skill directory walks against symlink cycles and excessive depth; sanitizes task cancellation errors; and adds a 2-second `SIGKILL` escalation fallback when tearing down remote PTY child shells.
  - **Native SEP-2640 Skills over MCP, user skills & upstream skill passthrough**: Serves built-in Muqun orchestration playbooks, user-installed `<config_dir>/skills/<name>/SKILL.md` directories, and upstream MCP server skills (live `resources/read` passthrough via `skills.read` and native `resources/read`) with official `skills/list`, `skills/get`, `resources/list`, `resources/directory/read`, and SEP-2549 cache hints.
  - **Native SEP-2663 MCP Tasks & Parallel Barrier Wakeup**: Implements `tasks/get` and `tasks/cancel` over Muqun's task store; adds `tasks.delegate(barrier_group)` so parallel sub-task fan-out coalesces into a single consolidated parent wakeup while immediately surfacing `waiting` children.
  - **MCP performance, redaction, ACP injection & effort ordering**: Caches the static MCP `ToolRouter` schema once, expands secret redaction to PEM private keys, credentialed URLs, and parent wakeup messages, unifies Muqun MCP injection across all 6 ACP agent drivers (Claude, Cursor, Antigravity, Copilot, Qoder, and Fx), and orders the `"none"` reasoning effort level before `"minimal"` in catalog effort sorting.
- **Interactive remote PTY WebSocket (`remote_pty_v1`)**: Added `GET /api/pty/ws` on Unix hosts, spawning the host owner's login shell in a real pseudo-terminal (`openpty`) over paired-device auth and E2EE v2 per-frame sealing (`FrameCodec`) with per-device/global slot limits, dynamic resize, revocation checks, and clean SIGHUP teardown so paired Desktop clients can run interactive remote terminals and `nvim`.
- **Model-led Multi-Agent Orchestration (MAO) and enhanced MCP tools**: Orchestration now defaults to Lead-Model orchestration (`auto_review: false`, advertised via `agent_orchestration_model_led_v1`, alongside `agent_orchestration_pool_v1` and `agent_orchestration_router_v1`) so Gateway does not force a cold Reviewer pass after every turn while still offering optional automatic code review, on-demand Ask Advisor, dynamic agent/model pools, and automatic quota failover. MCP adds batch `tasks.wait` (`task_ids`, up to 16 tasks, `all`/`any`), warm child session reuse (`tasks.delegate(reuse_task_id)`), rich `fleet.describe` with available models/modes and live 400 ms quota health, and automatic output reduction and secret redaction.
- **Instant cold-open session previews across all 11 agents**: Native tail readers for Claude Code, Antigravity, Cursor, Qoder, and GitHub Copilot CLI plus a universal encrypted SQLite `session_preview_cache` serve recent conversation history immediately on cold open after restarts or idle eviction. ACP recovery snapshots run asynchronously off the foreground open path, and Claude Code reuses cached `claude-agent-acp` binaries directly.
- **Orchestration task titles and attachments**: Orchestration tasks preserve real session titles across Desktop and mobile App Home views (dropping the legacy `"Orchestration"` placeholder from both `TaskView.label` and `TaskView.title`). Markdown inline `[label](file://...)` references are no longer promoted as broken `message_assets`, while bare absolute workspace file paths in prose and plain path-list fenced blocks (e.g. `/path/to/repo/docs/*.md`) are now resolved into fenced, authenticated `image_assets` so Mobile App and Desktop render them as clickable file cards. Remote WebSocket sync recovers stalled connections via ping/pong timeouts, and active ACP terminal followers extend their deadline cleanly.
- GitHub Copilot CLI is available as an opt-in local ACP agent. It uses the CLI's existing sign-in and exposes the session modes, models, permissions and usage supported by that CLI. Selecting Autopilot requires the owner's consent.
- Opening a large session can start with a bounded window of retained messages. Earlier items remain available through pagination. Claude usage is recovered from large transcripts, Pi reads its active branch using indexed native records, and Qoder can index large recovery journals on disk.
- Agent timeline delivery preserves attachments and the origin of a prompt. A queued message appears in conversation history when the provider delivers it. OpenCode receipts reconcile with the provider's own user message, including intentional repeated sends.
- Paired clients can recover pending approvals and questions on reconnect. Uploads support legacy Word, Excel and PowerPoint attachments identified by their file formats.

## Compatibility and upgrade

Linux and macOS packages are available for x86-64 and ARM64. Herdr 0.7.5 or later remains supported. Herdr collaboration features require 0.9.0 or later. Existing Apps can continue using their current endpoints. Optional capabilities such as retained history windows and pending-request recovery require client support.

Back up the Gateway store before upgrading, particularly from an older stable release. Finish any active agent turns and restart Gateway to load the new binary. Startup applies pending store migrations. If rollback crosses a schema change, restore the database backup that matches the earlier binary. Existing transport-encrypted pairings carry over. Older unencrypted devices must pair again on a Gateway configured to require encrypted transport.
