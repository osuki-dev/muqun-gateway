# v0.10.0

Agent collaboration, and a gateway that can bring its own terminal backend up.

**This release is backward compatible with every App already in the field.** The
API surface only gained fields and capabilities in this version; nothing was
removed or renamed. Apps decode gateway responses structurally and ignore keys
they do not know, so an older App talking to this gateway behaves exactly as it
did before. Upgrade the gateway on its own schedule — it does not wait on an App
release.

## Changes and fixes

- Agent collaboration. Agents carry an opaque `instance_id` — the identity of a
  process and its conversation, never a reusable pane id — so an assignment
  stays bound to the agent it was given to even if panes are closed and renumbered.
- Herdr terminal input preserves literal spaces by translating single-space key
  events to Herdr's named space key without changing event order.
- Installation can explicitly opt configured tmux/Herdr backends into starting
  with the gateway. Enter, no, invalid input, and noninteractive installs keep
  existing settings; new installations default to off.
- Running terminal servers are reused. A stopped tmux backend starts a detached
  shell, and Herdr starts headless. Startup is one-shot and does not block HTTP
  availability, repeatedly spawn processes, or repeatedly log failures.
- Service definitions preserve terminal child processes across gateway restarts.
- Linux service definitions quote paths and environment values safely, including
  spaces, quotes, backslashes, dollar signs, and systemd percent specifiers.
- The installer preserves custom tmux socket paths as one argument, including
  whitespace, quotes, and wildcard characters.
- Herdr-only installations use a standalone gateway, with guarded migration of
  existing plugin pairings. Live or inconsistent source installations require
  operator attention instead of silently replacing pairing identity.
- Herdr defaults and plugin migration use Herdr's XDG paths on macOS as well as
  Linux.
- Session responses include `connected`, so Apps can exclude stopped backends
  from the switcher without deleting their configuration.
- Explicit read-only file previews can resolve files under platform temporary and
  cache directories. Workspace file browsing remains workspace-scoped; preview
  lookups do not expose directory listings or grant write access.

## App compatibility

New capabilities advertised: `agent_collaboration`, `terminal_session_liveness`.
No capability was removed. Apps detect features by capability rather than by
gateway version, so nothing keys off the version number here.

- **An older App with this gateway** keeps working unchanged. It ignores the new
  `connected` and `instance_id` fields, and never asks for a capability it does
  not know about.
- **A newer App with an older gateway** also keeps working: when a session omits
  `connected`, the App fills it in from `/health` instead.
- Agent collaboration additionally requires a connected Herdr 0.9.0+ backend for
  the selected session. Where that is missing, ordinary terminal use is
  unaffected and the App explains what to upgrade.

## Upgrade

Existing configurations are left alone: **no backend is opted into autostart by
the upgrade.** Turn it on per backend when you want it:

```sh
muqun-gateway backend autostart <id> on|off
```

Reinstall the service after upgrading to apply the process-lifetime settings —
an existing service definition keeps the old one until it is rewritten. macOS
starts at user login; Linux boot startup requires user-service lingering.

Standard default and named Herdr sessions are supported for autostart. Custom
socket paths, whose persistence location is unknown, remain manual.

## Validation

`cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, and
`cargo test --locked` all pass on the merge commit: 503 tests passed, 0 failed,
19 ignored.

Backward compatibility above was verified against the App's own client code, not
only asserted: the gateway client performs no schema validation on responses, so
additive fields cannot be rejected, and the diff for this release removes no
field or capability.

**Not verified, and worth knowing before you rely on it:**

- Linux boot startup. The headless-start and reuse checks were run locally
  against installed Herdr and tmux, but no machine was rebooted, so
  start-at-boot behaviour on Linux is untested.
- A real paired App-to-Gateway-to-agent delivery check. Agent startup and prompt
  delivery changed in this release; the local checks and fixtures do not stand in
  for one live paired run.
